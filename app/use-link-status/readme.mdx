# useLinkStatus

`useLinkStatus` 是一个客户端组件钩子，用于追踪 `<Link>` 的 **待处理** 状态。当导航至新路由完成时，可使用它来显示内联视觉反馈（如旋转图标或文字闪烁效果）。

`useLinkStatus` 在以下情况下非常有用：

- 预取被禁用或正在进行中。
- 目标路由是动态的 **并且** 不包含 `loading.js` 文件，这将允许即时导航。

**注意：** 我们建议使用 `loading.js` 并且不要禁用预取。这允许 Next.js [即时导航](/loading) 到新路由，并在页面其余部分加载时显示加载状态。

## 待处理 UI 设计提示

- **保持微妙，避免布局偏移**：待处理指示器应感觉轻量且不显眼。为避免布局偏移，请将它们放在正常文档流之外（例如 `position: absolute`）或使用不会创建元素的 CSS 方法（例如动画渐变的 `background` 位置）。
- **优雅处理快速导航**：通过添加初始动画延迟（例如 150 毫秒）并将动画设置为不可见（例如 `opacity: 0`）或在父元素的裁剪边界之外（例如 `overflow: hidden` 和 `translate: -100%`）来防止快速导航时不必要的待处理 UI 闪烁。
- **将指示器放置在交互附近**：视觉反馈应出现在用户单击或点击的位置附近。这有助于加强反馈与其操作之间的联系。
- **主动设计**：即使在大多数导航快速的情况下，预先包含关键导航项的待处理指示器也是可以的。如果过渡是瞬时或快速的，指示器将没有机会显示。如果导航由于某种原因需要时间，用户将获得有用的反馈。

## 加载界面深度解析

Next.js 路由以服务器为中心。这有很多好处，但意味着导航需要往返于服务器以获取有关新路由的信息。

Next.js 通过预渲染、预取和流式传输等策略来缓解这种权衡。此外，开发人员可以使用 `loading.js` 和 `useLinkStatus` 等 API。

### 改善加载用户体验

当用户导航时（例如，单击 `<Link>`），在导航完全完成之前会有两个阶段：

1. **待处理阶段**：在导航和浏览器 URL 更新之前，**当**用户仍在当前路由上时。
2. **加载阶段**：在导航和浏览器 URL 更新之后，但**在**新路由的所有内容加载之前。

Next.js 提供了功能和 API 来改善这两个阶段的加载体验：

- **预取**：`<Link>` 预取路由以实现即时导航。静态路由默认完全预取。动态路由部分预取到最近的带有 `loading.js` 文件的片段。将片段的后备 UI 包含在预取中可以实现动态路由的即时导航。
- **待处理 UI**：使用 `useLinkStatus` 和 `useFormStatus` 在待处理阶段向用户显示视觉反馈。
- **即时导航和加载 UI**：使用 `loading.js` 为路由片段定义后备 UI。在导航时，这基本上跳过了待处理阶段，并立即向用户显示内容，同时其余内容正在加载。
- **流式传输**：使用 `<Suspense>` 边界进一步将服务器端工作拆分为更小的部分，并在加载阶段更早地向用户显示内容。
